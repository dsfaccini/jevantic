# Mission: Evaluate Jevantic's API design

## Why

Use a shared vocabulary to judge which parts of Jevantic make everyday decision code clearer and which responsibilities belong to its callers.

## Success looks like

- Distinguish a model primitive, a convenience API, and an application workflow in a concrete example.
- Explain why a typed answer and a correct model judgment are different guarantees.
- Compare an API proposal by the caller code it removes and the policy it introduces.

## Constraints

- Keep explanations short and grounded in the library's working examples.
- Introduce terms when they help assess the current design.

## Out of scope

No additional learning topics have been excluded.
